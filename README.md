## 📖 概要

### 🎮 ゲームのコンセプト
- **ジャンル**： 8方向パリィアクションゲーム
- **ゲームコンセプト**： マウスカーソルで斬撃方向を入力し、8方向の斬撃によって敵の攻撃をパリィするアクションゲーム。
Unreal Engine 5を使用して制作したアクションゲームです。

本作品はチームで開発を行い、Blueprintを用いてゲームシステムやゲームプレイの実装を行いました。

## 🤝 チーム開発について

3人チームで開発を行い、メインプログラマーとしてBlueprintによるゲームロジックの実装を担当しました。

- **役割分担**
  - **自分**： Blueprintを用いたゲームロジックの実装
  - **他メンバー**： 武器や敵のメッシュ、レベルマップ、Niagaraエフェクトの制作
  
  他のメンバーが制作したアセットを自分のプロジェクトにインポートし、ゲームロジックと組み合わせてゲーム内に組み込みました。

- **共同開発・機能の連携**
  他のメンバーから提案された機能を実装するとともに、制作されたアセットの仕様や調整方法を制作者に確認しながら開発を進めました。
  
- **課題への対応**
  - **Niagaraエフェクトの表示**： スポーン処理を実装してもエフェクトが表示されない問題が発生した際、制作者に相談して想定される表示位置を確認し、スポーン位置（Location）を調整しました。
  - **レベルマップの調整**： 他のメンバーが制作したレベルマップについて、制作者に調整方法を確認し、作業に反映しました。

この経験を通じて、ゲームロジックの実装だけでなく、他のメンバーが制作したアセットの仕様を理解し、相談・調整を行いながらゲームに組み込むことの重要性を学びました。

## 💻 担当範囲・実装したシステム

本作品では、メインプログラマーとしてBlueprintによるゲームロジック全般を担当しました。  
ゲームのコアとなる8方向パリィアクションをはじめ、Behavior Tree・Blackboard・EQSを用いた敵AIの構築、Level Sequenceを用いた必殺技の演出制作など、ゲームプレイから演出まで幅広く担当しました。

### 📌 主な担当範囲

| 分類 | 担当内容 |

| **AIシステム** | Behavior Tree・Blackboard・EQSを用いた敵AIの構築 |

## 🌟 技術的なアピールポイント

### 1. 8方向パリィアクションの実装
本作品のコアメカニクスである「マウスのドラッグ方向に合わせた8方向斬撃・パリィ判定」のロジックを判定精度と手触り（レスポンス）を意識して実装しました。

* **処理の構成**
  1. **入力方向のベクトル計算**: マウスカーソルの移動入力（2Dスクリーン座標）から角度（Angle）を計算し、360度を8方向（各45度）のセクターに割り当て。
  2. **攻撃・パリィ判定処理**: プレイヤーと敵の攻撃方向（ベクトル）の一致判定および、ジャストタイミングの判定ロジックを実行。
  3. **ヒットストップ・カメラワーク連動**: パリィ成立時にイベントを介してカメラシェイクやアニメーション再生、ヒットストップ処理を呼び出し。
* **設計上の工夫**
  * プレイヤーの入力デバイス感度や解像度による影響を受けにくくするため、ノーマライズ（正規化）した入力ベクトルを用いて角度計算を行いました。
  * アニメーション判定とヒット判定の同期にはAnimNotify（アニメーション通知）を活用し、ロジックとビジュアルの乖離を防ぎました。
* **解決した課題**
  * 判定フレームの入力揺らぎ対策として、方向判定にわずかな猶予範囲（マージン）を設けることで、プレイヤーが直感的に操作しやすい「手触りの良さ」を実現しました。

---

### 2. Behavior Tree・Blackboard・EQSによる敵AI構築
プレイヤーとの駆け引きを楽しめる対戦型敵AIを構築するため、アンリアルエンジンの標準AI機能を活用した設計を行いました。

* **構成とそれぞれの役割**
  * **Blackboard**: プレイヤーの位置、警戒度、ターゲットとの距離、現在選択されている攻撃パターンなどの状態変数を一元管理。
  * **Behavior Tree**: 「索敵」「距離詰め」「攻撃選択」「防御/パリィ」「待機」のロジックを優先度付きのタスクノードで制御。
  * **EQS (Environment Query System)**: プレイヤーの周囲にある「最適な移動位置（間合いをとる、背後に回り込む等）」を環境検索して点数付けし、最も評価の高いグリッド位置へAIを移動させる処理を実装。
* **設計上の工夫**
  * 単調な行動パターンにならないよう、プレイヤーの攻撃頻度や距離に応じてBlackboard変数を動的に書き換え、行動分岐を柔軟に変化させました。
* **解決した課題**
  * AIの判断処理（EQSクエリ等）が毎フレーム実行されて負荷がかかるのを防ぐため、更新間隔の制御や状態変化時のみクエリを発行するイベント駆動型の設計を徹底しました。

---

### 3. 発射物のオブジェクトプール（Object Pooling）
弾幕や連続発射される弾などの生成・破棄（Spawn/Destroy）による処理負荷を抑えるため、自作のオブジェクトプールシステムを実装しました。

* **実装方法**
  * **事前生成と配列管理**: ゲーム開始時（または必要時）に一定数の発射物Actorを生成（Spawn）しておき、非アクティブ（非表示・コリジョンOFF）状態で配列に格納。
  * **再利用フロー**: 発射が必要になった際、配列から非アクティブなActorを取得（Get）して位置・ベクトルを設定し、アクティブ化（表示・コリジョンON）。
  * **返却フロー**: 画面外到達時や着弾時にはDestroyせず、ステータスを初期化してプール配列にリセット（返却）。
* **工夫した点**
  * プール内の弾が不足した際にもクラッシュや処理落ちを起こさないよう、一時的な動的拡張（追加Spawn）ロジックを設けるなど安全な参照管理を行いました。
* **解決した課題**
  * アクションゲームにおいて最もフレームレート低下の原因になりやすい「大量のActor Spawn/Destroy処理」を排除し、ガベージコレクション（GC）のスパイクによるコマ落ちを防止しました。
